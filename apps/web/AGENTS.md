# apps/web SKILL

apps/web 프로젝트에서 작업할 때 참고하는 가이드입니다.

## Scope

- Docusaurus 기반 ui-kit 패키지 랜딩 페이지 + 컴포넌트 문서 (포트 3000)
- 컴포넌트별 인터랙티브 플레이그라운드(모든 variant/props 조합)는 계속 `apps/docs`(Storybook)가 담당함 — 여기 `docs/`는 컴포넌트를 하나씩 채워나가는 설명 + 라이브 데모 위주 문서이고, 전수 커버리지를 목표로 하지 않음
- 새 컴포넌트 문서 페이지 추가 패턴: **파일 경로**는 `packages/ui/src/components`와 동일한 계층(atoms/molecules/organisms/templates)으로 `docs/components/{tier}/{kebab-case-name}.mdx` 작성 + 필요하면 `src/demo/{kebab-case-name}-demo.tsx`에 라이브 데모 컴포넌트 작성. **사이드바 그룹핑**은 파일 경로의 계층이 아니라 해당 컴포넌트의 Storybook story `title` 프리픽스(예: `Data Entry/Select`)를 따라 `sidebars.ts`에 항목 추가 — 랜딩 페이지 `CATEGORIES`와 동일한 분류(General/Data Entry/Data Display/Feedback/Navigation/Layout). `docs/components/atoms/tag.mdx` + `src/demo/tag-demo.tsx`가 참고할 템플릿

## Key Paths

- `src/pages/`: 커스텀 페이지 (현재는 홈페이지 하나)
- `docs/`: 컴포넌트 문서 페이지. **파일 경로는 계층별**(`components/{tier}/`)이지만 **사이드바는 기능별**로 그룹핑되어 있어 둘이 일치하지 않을 수 있음 (`sidebars.ts` 참고)
- `src/demo/`: 문서 페이지에 임베드하는 라이브 데모 컴포넌트
- `src/components/`: `DemoTheme` 등 페이지에서 쓰는 컴포넌트
- `src/css/custom.css`: Tailwind + `@repo/ui/style.css` 진입점
- `static/`: 정적 리소스 (favicon 등)
- `docusaurus.config.ts`: 사이트 설정 (navbar/footer, Tailwind postcss 플러그인 연결)
- `sidebars.ts`: 문서 사이드바 (수동 관리 — 새 페이지 추가 시 여기도 같이 갱신). `pnpm --filter web check-orphaned-docs`가 이 파일과 `docs/`의 어긋남을 잡아준다
- `scripts/check-orphaned-docs.mjs`: `docs/`의 모든 페이지가 `sidebars.ts`에서 도달 가능한지 검사 (CI 필수)

## Rules

- `@repo/ui/style.css`는 워크스페이스 안에서 소스 CSS(`packages/ui/src/globals.css`)로 resolve되므로, 이 앱이 자체 Tailwind 빌드(`configurePostCss`)를 돌려야 유틸리티 클래스가 생성된다 — 이 설정을 건드릴 때는 `docusaurus.config.ts`의 주석을 참고
- 공용 UI는 가능하면 `@repo/ui`를 우선 재사용
- **다크모드는 Docusaurus의 `data-theme` 속성이 그대로 구동한다.** ui-kit의 dark variant는 `&:is(.dark *, [data-theme='dark'] *)`이고 토큰 블록도 `.dark, [data-theme='dark']`를 함께 받으므로, Docusaurus가 `<html>`에 붙이는 `data-theme='dark'`만으로 모든 컴포넌트가 이미 테마링된다 — 데모를 감싸는 별도 wrapper가 필요 없다 (ui-kit의 `Config` wrapper도 안 씀: 자기 children 안쪽 div에만 마커를 붙여서 페이지 전체를 덮지 못한다). **`<html>`에 `.dark`를 직접 토글하는 방식은 쓰지 않는다** — Docusaurus는 `class` 속성을 `react-helmet-async`로 소유해서 라우트가 바뀔 때마다 통째로 덮어쓰므로, imperative하게 붙인 클래스는 살아남지 못한다 (#393에서 `DemoTheme`을 이 이유로 제거). 이 의존은 `packages/ui`의 `check-data-theme-dark` 리그레션 체크가 지켜준다
- **페이지 배경/본문 텍스트 색은 Infima가 소유한다.** `custom.css`는 `html`/`body`를 칠하지 않고 `--ifm-*` 토큰만 덮어쓰며, 이건 형제 Docusaurus 사이트(use-hooks, live-editor)와 다크모드 색을 맞추기 위한 것이다 (배경 `#1b1b1d`, 본문 `#e3e3e3`). Infima는 페이지 배경을 **`<body>`가 아니라 `<html>`에** 칠하므로(`html { background-color: var(--ifm-background-color) }`), `body`에 배경을 주면 두 요소가 어긋난다 — 라이트 모드에서는 Infima 토큰이 `transparent`라 body 배경이 캔버스로 전파돼 가려지지만, 다크 모드에서는 불투명 `#1b1b1d`가 전파를 막는다. 게다가 Docusaurus Layout이 `html, body { height: 100% }`(min-height 아님)를 고정해 body 박스가 1 뷰포트 높이뿐이라, 스크롤하면 `html` 색이 드러난다 (#391, #392). 페이지 색을 바꿀 일이 생기면 `body`가 아니라 `--ifm-background-color`를 `:root`와 `html[data-theme='dark']` **양쪽에** 재정의한다
- **문서 페이지를 추가/이동/삭제하면 `sidebars.ts`도 같이 고친다.** 사이드바가 전부 수동(`autogenerated` 없음)인데 Docusaurus는 어떤 사이드바도 참조하지 않는 문서에 대해 경고하지 않는다 — 그래서 CodeEditor 페이지가 ui-kit#347에서 추가된 뒤 ui-kit#352에서 손으로 발견할 때까지 URL로만 접근 가능한 상태였다. `pnpm --filter web check-orphaned-docs`(CI 필수 단계)가 양방향으로 검사한다: 사이드바에 없는 문서(orphan)와 파일이 없는 사이드바 항목(dangling)
